DBus 工具概述

dbus命令常用的两个工具：dbus 和 busctl

dbus 命令

  • DBus的基本命令行工具
  • 提供与DBus总线通信的能力
  • 可以发送和接收DBus消息
  • 执行方法调用、查询对象和接口
  • 通用的DBus操作工具
  • 以DBus消息的原始格式输入输出
  • 几乎所有DBus实现都会提供

busctl 命令

  • 专门用于查看、控制和分析DBus总线状态
  • 显示和监视总线上的对象、接口和信号
  • 查询对象的属性和方法
  • 输出以人类可读的方式呈现
  • 以类似表格的格式显示信息
  • 可将输出转储到文件中
  • 由systemd项目提供
命令格式对比：
  • dbus <command> [options] <bus_name> <object_path> [<interface_name>]
  • busctl [options] <subcommand> [arguments...]

options一般包括--system和--session，当自定义了一个会话总线时一般使用--session选项

一、dbus 命令

1. 获取当前DBus总线中的所有总线名称

标准方法：org.freedesktop.DBus.ListNames

$ dbus-send --system --type=method_call --print-reply --dest=org.freedesktop.DBus / org.freedesktop.DBus.ListNames

2. 根据上层对象路径查找下层对象路径

标准方法：Introspect

$ dbus-send --system --type=method_call --print-reply --dest=bus_name 上层对象路径 org.freedesktop.DBus.Introspectable.Introspect
示例：当前我们想要看到bus name是 xyz.openbmc.PSU.Manager 下的对象路径可以执行以下命令：
$ dbus-send --system --type=method_call --print-reply --dest=xyz.openbmc.PSU.Manager / org.freedesktop.DBus.Introspectable.Introspect

命令中的 / 表示该bus name下的根节点，反馈信息是以xml的形式打印出来，可以看到其中的node name为xyz，这里的node name其实就是对象路径的每一个节点，例如 /xyz/openbmc/psu，xyz、openbmc都是对象路径的节点。

当我们需要继续往下查看xyz节点下的节点时，只需要将上述命令的 / 更换为 /xyz 即可，这样一层一层的往下查询。

3. 查找特定object path的service及其interface

标准方法：GetObject

$ dbus-send --system --type=method_call --print-reply --dest=xyz.openbmc_project.ObjectMapper /xyz/openbmc_project/object_mapper xyz.openbmc_project.ObjectMapper.GetObject string:"obj路径" array:string:
通过查看该method可以看到该方法存在两个输入参数，第一个输入参数就是对象路径，在使用时需要确保参数正确。

4. GetSubTree 方法

使用GetSubTree方法可以在指定的subtree中查找实现某个interface的object、service和interface。

5. GetAncestors

查找实现特定interface的object的所有祖先。

二、busctl 命令

1. busctl tree

以树状结构显示DBus对象的层次关系。

$ busctl tree

2. busctl introspect

获取指定对象的接口和方法的详细信息。

$ busctl introspect --system busname objpath

3. busctl list

列出系统总线上的所有对象。

$ busctl list

4. busctl get-property

获取指定对象的属性值。

$ busctl get-property [<bus>] <name> <object> <interface> <property>
  • <bus>（可选）：指定要操作的DBus总线，可以是--system、--user或<bus-name>。如果未指定总线，则默认为系统总线。
  • <name>：bus name。
  • <object>：指定对象路径。
  • <interface>：指定接口名称。
  • <property>：指定要获取的属性名称。

5. busctl monitor

实时监视DBus总线上的消息和信号。

$ busctl monitor [<bus>]
  • <bus>（可选）：指定要监视的DBus总线，可以是--system、--user或<bus-name>。如果未指定总线，则默认同时监视系统总线和用户总线。

6. busctl status

显示系统总线的连接状态和有关进程的信息。

$ busctl status [<bus>]
  • <bus>（可选）：指定要查询的DBus总线，可以是--system、--user或<bus-name>。如果未指定总线，则默认同时查询系统总线和用户总线。

7. busctl set-property

设置指定对象的属性值。

$ busctl set-property [<bus>] <name> <object> <interface> <property> <type> <value>
  • <bus>（可选）：指定要操作的DBus总线，可以是--system、--user或<bus-name>。如果未指定总线，则默认为系统总线。
  • <name>：bus name。
  • <object>：指定对象路径。
  • <interface>：指定接口名称。
  • <property>：指定要设置的属性名称。
  • <type>：指定属性的值类型，例如i表示整数，s表示字符串，b表示布尔值等。
  • <value>：指定要设置的属性值。

8. busctl call

调用指定对象上的方法。

$ busctl call [<bus>] <name> <object> <interface> <method> 参数类型 [arguments...]
  • <bus>（可选）：指定要操作的DBus总线，可以是--system、--user或<bus-name>。如果未指定总线，则默认为系统总线。
  • <name>：bus name。
  • <object>：指定对象路径。
  • <interface>：指定接口名称。
  • <method>：指定要调用的方法名称。
  • [arguments...]：可选的方法参数列表。方法的参数数量和类型根据具体的接口和方法而定。
PS：参数类型注意事项
  • 参数类型含有a（即数组，比如说a(ssb)，一个数组，数组中的每个成员是一个结构体，结构体里面是两个string和一个bool的量），此时的参数类型是需要用""括起来，如"a(ssb)"。
  • 当参数类型包含a（即数组），在后面的arguments需要写当前传入参数数组有几个成员，比方说参数类型为"a(ssb)"，参数就应该写 1 wei tianxiang true，也可以写2 wei tianxiang true wei xiaobao false等等。
示例：
$ busctl call xyz.openbmc_project.BmcConfig.Manager /xyz/openbmc_project/bmcConfig xyz.openbmc_project.BmcConfig.BmcConfig ExportBmcConfig b 1

9. 可变类型参数 v

当参数中存在 v 时，表示是一个可变类型，在实际调用时需要指定v是哪种类型。

示例：
$ busctl call xyz.openbmc_project.Inventory.Manager /xyz/openbmc_project/inventory/cpu/CPU1 org.freedesktop.DBus.Properties Set ssv xyz.openbmc_project.Inventory.Item PrettyName s 3

上述set的参数是 ssv，在传入最后一个v参数前提前指定了v参数为 s。

复杂示例：
$ busctl call xyz.openbmc_project.Smtp.Manager /xyz/openbmc_project/AlertLog xyz.openbmc_project.Smtp.Smtp SetMailInfo "b(susb)(sss)(sus)a(ssb)" true 10.0.15.238 25 None false zhangda@sugon.com zhangda 111111 subject 1 Normal 1 zhangda@sugon.com zhangda true

10. busctl monitor 监控dbus变化

示例：监控属性变化
$ busctl --match="type='signal',interface='org.freedesktop.DBus.Properties',member='PropertiesChanged',path_namespace='/xyz/openbmc_project/control/host0/boot'" --no-pager monitor

上述命令用于监控属性变化，类似响应如下：

> Type=signal  Endian=l  Flags=1  Version=1 Cookie=240  Timestamp="Tue 2025-02-25 07:21:44.009992 UTC"
  Sender=:1.32  Path=/xyz/openbmc_project/control/host0/boot  Interface=org.freedesktop.DBus.Properties  Member=PropertiesChanged
  UniqueName=:1.32
  MESSAGE "sa{sv}as" {
          STRING "xyz.openbmc_project.Control.Boot.Source";
          ARRAY "{sv}" {
                  DICT_ENTRY "sv" {
                          STRING "BootSource";
                          VARIANT "s" {
                                  STRING "xyz.openbmc_project.Control.Boot.Source.Sources.Disk";
                          };
                  };
          };
          ARRAY "s" {
          };
  };

可以看到sender的唯一名为 :1.32，检查 :1.32 可得知为服务 xyz.openbmc_project.Settings，即在该服务下的对象路径 /xyz/openbmc_project/control/host0/boot 的属性 BootSource 发生了变化。

查找哪个服务设置了属性变化

$ busctl monitor --match="type=method_call,path=/xyz/openbmc_project/control/host0/boot"

更改match为 method_call，可以得到类似的响应：

> Type=method_call  Endian=l  Flags=0  Version=1 Cookie=3134  Timestamp="Tue 2025-02-25 07:26:12.898902 UTC"
  Sender=:1.189  Destination=xyz.openbmc_project.Settings  Path=/xyz/openbmc_project/control/host0/boot  Interface=org.freedesktop.DBus.Properties  Member=Set
  UniqueName=:1.189
  MESSAGE "ssv" {
          STRING "xyz.openbmc_project.Control.Boot.Source";
          STRING "BootSource";
          VARIANT "s" {
                  STRING "xyz.openbmc_project.Control.Boot.Source.Sources.RemovableMedia";
          };
  };

> Type=method_call  Endian=l  Flags=0  Version=1 Cookie=3135  Timestamp="Tue 2025-02-25 07:26:12.899190 UTC"
  Sender=:1.189  Destination=xyz.openbmc_project.Settings  Path=/xyz/openbmc_project/control/host0/boot  Interface=org.freedesktop.DBus.Properties  Member=Set
  UniqueName=:1.189
  MESSAGE "ssv" {
          STRING "xyz.openbmc_project.Control.Boot.Mode";
          STRING "BootMode";
          VARIANT "s" {
                  STRING "xyz.openbmc_project.Control.Boot.Mode.Modes.Regular";
          };
  };

在上述响应中搜索 Set 的method可以看到sender的唯一名为 :1.189，搜索 :1.189 唯一名的服务为 bmcweb：

$ busctl list | grep -i 1.189
:1.189 932 bmcweb root :1.189 bmcweb.service - -
xyz.openbmc_project.BmcWeb 932 bmcweb root :1.189 bmcweb.service - -
常见match类型：除了上述match，最常见的还有接口增加等监控方式。
