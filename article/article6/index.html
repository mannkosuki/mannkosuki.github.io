一，什么是 Bitbake

Bitbake 是一个开源的构建工具，通过提供必要的元数据，Bitbake 能够构建出 bootloader 到应用层各种各样的软件包。

Bitbake 有几个比较突出的特点：

  • Bitbake 是以任务为单位进行构建，而这些任务通常是由菜谱文件（.bb，也称配方文件/Recipes）、配置文件（.conf）和类文件（.bbclass）所定义。
  • 通过添加一些变量，Bitbake 可以从本地，甚至从远程服务器获取要用的源码或补丁等文件。

Bitbake 可以从这里下载：https://github.com/openembedded/bitbake

二，Bitbake 工程布局

Bitbake 工程通过 layer 目录和 build 目录组织。layers 目录包含配置文件、class 文件和 recipes。

1，Layer 目录

Layer 目录包含配置、任务和目标描述。常用 meta-'something' 命名 Layer 目录。

2，Build 目录

Build 目录是 bitbake 命令被执行的地方。在这里，bitbake 期望能找到其初始配置文件，并将生成的所有文件放在这个目录下。

三，最小工程

创建4个文件：bblayers.conf + base.bbclass + bitbake.conf + layer.conf，形成一个最小工程。

bbTutorial/
├── build
│   ├── bitbake.lock
│   └── conf
│       └── bblayers.conf
└── meta-tutorial
    ├── classes
    │   └── base.bbclass
    └── conf
        ├── bitbake.conf
        └── layer.conf

1，需要的配置文件

build/conf/bblayers.conf，这个文件是 Bitbake 在其工作目录中（即 build 目录）期望找到的第一个文件。现在我们用以下内容创建一个 bblayers.conf 文件：

BBPATH := "${TOPDIR}"   #BBPATH用于定位.bbclass文件和.conf文件。添加当前目录到BBPATH，TOPDIR(即build目录)被BitBake设置为当前工作目录
BBFILES ?= ""           #初始设置BBFILES变量为空，Recipes在后面会添加
BBLAYERS = "${TOPDIR}/../meta-tutorial" #添加我们 meta-tutorial 目录到 BBLAYERS 变量。
                                        #当 BitBake 开始执行时，它会搜索所有给定的 layer 目录，以便获得其他配置。

meta-tutorial/conf/layer.conf，每个 layer 都需要一个 conf/layer.conf 文件，用来指定该 layer 目录中有哪些 recipes 及其路径。现在我们用以下内容创建它：

BBPATH .= ":${LAYERDIR}"   #LAYERDIR是BitBake传给layer.conf，表示当前layer的目录。
                           #我们添加该路径到BBPATH变量. BBPATH is used to search for configuration and class files under the 'conf' and 'classes' directories, respectively
BBFILES += ""              #BBFILES告诉BitBake recipes(.bb文件)在哪，现在我们没有添加任何东西，但是一会儿我们会改变它。

meta-tutorial/classes/base.bbclass，该 class 是 yocto 最基本的类，所有的 recipes（.bb文件，菜谱文件）都直接或间接的继承该类。It is always included automatically for all recipes and classes.

meta-tutorial/conf/bitbake.conf，bitbake在启动时会解析 bitbake.conf，它包含一系列变量。bitbake.conf 会装载用户提供的 local.conf 文件。

上面两个文件可以从 Bitbake 安装目录中获取。这些文件位于文件夹 bitbake-$version/conf 和 bitbake-$version/classes 中。只需要将他们复制到 tutorial 项目中。

注意事项：".=" 和 "+=" 以不添加空格和添加空格的方式，将追加值赋给一个变量

2，Bitbake 搜索路径

Bitbake 会搜索 BBPATH 指定的路径。目前我们给 BBPATH 赋值了 ${TOPDIR} 和 ${LAYERDIR}。

四，第一次运行

创建上述四个配置文件后，在终端 cd 到 build 目录，这是我们的工作目录。后面我们会一直在 build 目录运行 bitbake 命令，以便 bitbake 可以找到相应的 conf/bblayers.conf 文件。

现在，在 build 目录下不带任何参数运行 bitbake 命令：

$ bitbake

1，Cache 位置

Bitbake 会在 cache 目录中缓存 meta 数据。这会帮忙加速后面执行的命令。

我们可通过在 bitbake.conf 文件中添加一个变量，解决 cache 找不到的问题：

CACHE = "${TMPDIR}/cache/default"

下一步是添加一个 recipe，需要两个步骤：

  • 使 bitbake 可以找到 recipes
  • 写第一个 recipe

2，添加一个 Recipe 到 Tutorial Layer

Bitbake 需要知道一个 layer 提供了哪些 recipes，可以通过编辑 meta-tutorial/conf/layer.conf 文件告诉 bitbake 加载所有的 recipe：

BBPATH .= ":${LAYERDIR}"
BBFILES += "${LAYERDIR}/recipes-*/*/*.bb"

recipe 文件的扩展名是 .bb，如果我们通过通配符的方式，只用一行就可以告诉 BitBake 加载所有 recipes。

通常 recipes 有自己的目录，并以 groups 的形式收集在一起，也就是说把有关联的 recipes 放在同一个目录。

现在 BitBake 已经知道从哪找 recipe，我们可以开始添加第一个 recipe 了。按通常的做法，我们创建目录 meta-tutorial/recipes-tutorial/first，并在此创建第一个 recipe。Recipe 文件也有通用的命名方法：{recipe}_{version}.bb

六，Classes 和 Functions

下一步：

  • 添加一个 class
  • 添加一个使用 class 的 recipe
  • 探索 functions

1，创建 mybuild Class

创建一个不同的 build 函数，并共享。

先在 tutorial layer 创建一个 class 文件：meta-tutorial/classes/mybuild.bbclass

addtask build
mybuild_do_build () {
   echo "running mybuild_do_build."
}

EXPORT_FUNCTIONS do_build

在 mybuild.bbclass 中，我们添加了一个 build task，它也是一个简单的 shell 函数。mybuild_do 前缀的依据是 class 中 task 定义的规范 classname_do_functionname。

EXPORT_FUNCTIONS 使该 build 函数可以被这个 class 的使用者使用，如果不添加这行，则它不会覆盖 base class 中的 build 函数。

现在，已可在第二个 recipe 中使用这个 class。

2，在第二个 Recipe 中使用 myclass

这里添加一个小目标，在 build 任务前先运行一个 patch 函数，这里需要一些 python 的用法。

依据 bitbake 的命名规范，我们添加一个新的 recipe 目录，并在该目录内添加一个 recipe 文件 meta-tutorial/recipes-tutorial/second/second_1.0.bb：

DESCRIPTION = "I am he second recipe"
PR = "r1"        #(1)像first recipe那样定义DESCRIPTION和PR
inherit mybuild  #(2)继承mybuild class，让myclass_do_build成为默认build task

def pyfunc(o):   #(3)纯python函数pyfunc获取一些参数，并根据该入参运行python dir函数
    print(dir(o))

python do_mypatch () {    #(4)bitbake python函数mypatch添加并注册成一个task，该task要在build函数前执行。
  bb.note ("runnin mypatch")
  pyfunc(d)    #(5)mypatch函数调用pyfunc函数，并传入全局bitbake变量d。d (datastore)由bitbake定义，并一直可用。
}

addtask mypatch before do_build #(6)mypatch函数被注册成一个task，并要求在build函数前执行。

七，Bitbake Layers

典型 BitBake 工程包含多个 layer。通常 layer 包含一个特定主题，比如基础系统、图像系统等。一些工程可以包括不止一个构建目标，每个目标由不同的 layers 组成。例如，构建一个带 GUI 组件或不带 GUI 组件的 Linux 发行版本。

1，添加一个 Layer

通过以下步骤添加一个新的 layer：

  • 创建一个新的 layer 目录 — 创建一个新的目录叫 meta-two
  • 创建 layer 配置 — 添加 meta-two/conf/layer.conf 文件，该文件和 tutorial layer 的一样：
BBPATH .= ":${LAYERDIR}"
BBFILES += "${LAYERDIR}/recipes-*/*/*.bb"
  • 告诉 bitbake 有新的 layer — 编辑 build/conf/bblayers.conf，扩展 BBLAYERS 变量：
BBLAYERS = " \
  ${TOPDIR}/../meta-tutorial \
  ${TOPDIR}/../meta-two \
"
  • 添加 recipes 到 layer

3，扩展 Layer 配置

在 layer 的 layer.conf 文件中，定义优先级和其他配置值。为配置 layer 的优先级，需要添加新的定义到已有的 layer.conf。以 meta-tutorial/conf/layer.conf 开始，添加：

# append layer name to list of configured layers
BBFILE_COLLECTIONS += "tutorial"
# and use name as suffix for other properties
BBFILE_PATTERN_tutorial = "^${LAYERDIR}/"
BBFILE_PRIORITY_tutorial = "5"
LAYERSERIES_CORENAMES = "bitbakeguilde"
LAYERVERSION_tutorial = "1"
LAYERSERIES_COMPAT_tutorial = "bitbakeguilde"

使用的变量在 BitBake 使用手册有很好的说明，这里不重复。这里使用 layer 的名字做为其他变量的后缀。

同样的，修改 meta-two/conf/layer.conf：

BBFILE_COLLECTIONS += "two"
BBFILE_PATTERN_two = "^${LAYERDIR}/"
BBFILE_PRIORITY_two = "5"
LAYERVERSION_two = "1"
LAYERDEPENDS_two = "tutorial"
LAYERSERIES_COMPAT_two = "bitbakeguilde"
